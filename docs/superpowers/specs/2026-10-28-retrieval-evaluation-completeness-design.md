# 完整 MRR 与模型记录：小范围设计

用户已要求补齐完整 MRR、模型版本记录并原生执行，禁止推送。代码基线为组员的 `0112c82`，复用已附加 worktree；保留旧本地报告及所有历史测量。

采用现有 HTTP 评估脚本，不增加生产 API、数据库列、provider 框架或离线搜索功能。曾考虑仅把 top-k 改成 50，但返回条数不足不能证明整个课程都已回填；因此使用已校验 PDF 经现有 parser 生成的 Chunk 文本摘要、文档及页号 manifest 校验完整返回集合。另一个方案是新增生产元数据接口；本次无需扩大 API 契约，模型记录采用明确的人工声明或本地进程生成的 receipt，并始终注明 HTTP API 未核实该声明。

完整模式一次请求全部已校验 Chunks，额外探测一个位置以发现意外尾部（至少原 top-k，最多现有 API 上限 50），保留全部结果。因此可证明完整性的夹具上限为 49，本 MIT 夹具为 46，实际请求 47。只有集合完整且每题 canonical IDs 一致才计算完整 anchor MRR（主指标 `mrr`）与页 MRR；Top 1/3/5 及截断 MRR 仍保留，后者对第 K 名之后计零。部分向量、内容不符、达到 50 无法探测、异常或中途语料改变均 blocked，聚合指标为空。旧内部 bounded 调用仍明确记录 `ranking_complete=false`，CLI 新运行必须提供 manifest 和模型记录。

模型记录包括真实逻辑 provider/model、应用 revision、原生/存储维度、实际存储配置 ID、上游模型版本（未知为 null）、来源和可获得的运行库版本。人工声明不伪称服务端验证，本地 BGE 仍保留已有存储 ID 兼容旧数据，但逻辑 provider 明确为 fastembed，不再靠文件名推断。拒绝额外字段，防止意外把 key/任意环境写入结果；记录文件不覆盖。

不追补旧 Top-5 JSON 中不存在的排名，不推算历史完整 MRR，不把 stub 测试当成实测。不增加依赖，不安装本地模型，不调用收费 API。最终输出中文状态、测试证据及以后提供 embedding API key 后的命令。无 API 的最终产品能力仅说明现有操作和可选关键词检索，不在本次实现。
